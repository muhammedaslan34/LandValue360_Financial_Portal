# ملاحظات الإصدار 2.1.0

## تجربة الاستخدام

- استبدال «تشغيل Base Case» بـ«تشغيل التحليل المالي».
- إنهاء مسار إدخال المشروع بزر «الانتقال إلى التحليل المالي» بدلاً من زر «التالي» غير الفعال.
- إزالة إرسال المشروع إلى فريق التحليل من رحلة المستخدم العادي؛ التحليل ينفذ مباشرة داخل البوابة.
- فصل النتائج إلى: المشروع، المطور، صاحب الأرض، وتقييم الأرض والتفاوض.
- واجهة عربية/إنكليزية قابلة للتبديل مع إبقاء المستخدم في الصفحة نفسها.
- طي فحوص السياسة والمصالحة وProvenance افتراضياً.
- إضافة رسم تفاوضي يوضح Fair Floor وBalanced وTechnical Ceiling والعرض الحالي.
- إعادة تصميم التقرير القابل للطباعة ليشمل المعلومات والافتراضات والنتائج والتوصية والتدفقات والمراجع الفنية.

## الصلاحيات والافتراضات المتقدمة

- إخفاء التمويل ومنحنيات المبيعات والكلف وخطط التحصيل عن المستخدم العادي.
- إضافة صلاحية `financial.advanced_inputs` للمحلل ومدير الفريق ومدير المنصة.
- فرض Server-side allowlist يمنع تجاوز الإخفاء بإرسال حقول متقدمة يدوياً إلى API.
- نقل الافتراضات المتقدمة الافتراضية إلى Financial Policy Version قابلة للإدارة والتأريخ.
- الوضع الافتراضي بلا تمويل، مع S-Curve للمبيعات وBell للكلف وخطة تحصيل 20/30/50.

## التصحيحات المالية

- إجمالي التزام حقوق الملكية يشمل المساهمة الافتتاحية، ويحول للمحرك كرصيد افتتاحي زائد قدرة سحب إضافية فقط.
- حقول النسب في الواجهة تستقبل 35 بمعنى 35%.
- Fair Floor شبه الصفري لا يعرض كقيمة عادلة؛ يظهر «غير مثبت» عندما لا يوجد مرجع اقتصادي موجب.
- فصل Residual Land Value عن مقابل العقد والمجال التفاوضي، وتعريفه كمؤشر قدرة تطويرية قبل مقابل الأرض.
- إضافة تدقيق مستقل للتدفقات وXNPV/XIRR وحالات `SUPPORTED` و`CONDITIONAL` و`BLOCKED`.

## تقوية الفصل بين المستخدم العادي والمحلل

- تنقيح استجابات API للمستخدم العادي بحيث لا تعيد Finance Model أو منحنيات البيع والكلف أو Collection Rules المتقدمة.
- منع `include_full=true` للمستخدم غير المخول.
- منع المستخدم العادي من تحديد Policy Version أو Engine Version يدوياً عند إنشاء Calculation Run.
- إضافة endpoint تدقيق مختصر لكل تشغيل من دون كشف المدخلات المتقدمة.
- المحافظة على أي Advanced Override ثبته محلل عند قيام المستخدم العادي بتعديل المدخلات الأساسية.
